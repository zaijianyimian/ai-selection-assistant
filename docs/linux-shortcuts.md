# Linux 快捷键

Ubuntu GNOME Wayland 可在应用「偏好设置 → 翻译偏好」主动启用系统快捷键。X11 和 Windows 继续使用原生注册。其他 Wayland 桌面可在系统设置中手动添加自定义快捷键，执行：

```text
/usr/bin/ai-selection-assistant --translate-clipboard
```

## 首次启用与使用

1. 安装 DEB 后打开应用。安装和升级不会自动修改任何用户的快捷键。
2. 在设置中保存期望组合键；默认 Ctrl+Shift+Q。存在未保存改键时，先保存再启用。
3. 点击「启用系统快捷键」。出现可见冲突时换一个组合键；应用不会覆盖竞争绑定。
4. 在浏览器等应用先 Ctrl+C 复制文字，再按快捷键。应用未运行时会启动，运行中则将任务转交原实例。

“系统已配置 · 待按键验证”表示读回了配置，不代表桌面一定投递该按键。若无反应，请更换组合键并检查系统快捷键。检测覆盖 GNOME 自定义和可读的常见系统组合键，不能穷举合成器保留键。无文本、图片剪贴板、缺少 wl-paste 或权限失败会显示错误，不向模型发送替代文字。

GNOME 自动管理需要用户 GNOME 会话、gsettings、相关桌面 schema，以及从标准安装位置运行的应用。缺少工具时安装 `libglib2.0-bin` 和 `wl-clipboard`；缺少 GNOME 桌面 schema 不会强制安装整个桌面，界面会降级为手动说明。开发构建和非标准安装位置只提供手动方式，避免错误修改已安装版本的绑定。

## 重启、升级与外部修改

绑定使用固定的应用专属路径和命令，不带进程编号或临时 D-Bus 地址。退出应用不会删除绑定；正常重启只检查，不重复添加，也不每次弹配置对话框。升级后应退出旧应用再启动新版本，安装器不会强杀旧进程。

系统中修改了组合键，应用展示实际值；系统中删掉了条目，应用提示未配置/外部变更。点击「刷新状态」只读检查；点击「重新应用已保存快捷键」才恢复应用保存的组合键。若专属路径已被其他命令使用，应用拒绝接管或删除，请在 GNOME 设置中手动处理。应用不自动收编其他路径上的手工绑定，也不会清理微信绑定。

启用信息保存在本机 `desktop-shortcut.json`，不与主题、语言等偏好同步。Wayland 始终先复制，不模拟按键获取选区；浮窗位置由桌面管理，同次运行可保留手动拖动位置，不承诺跨重启位置恢复。

## 失败恢复与停用

启用、改键和停用会在外部写入前保存不含密钥或剪贴板内容的恢复记录。操作失败时恢复之前的自身绑定及本机状态，保留其他应用的配置；补偿失败则保留错误并阻止模型请求，不能把部分成功当成保存成功。

桌面操作中断时，点击「恢复快捷键操作」恢复先前状态，然后再试。若提示是设置恢复（例如同时改动凭据或记忆设置时失败），请重新输入或明确删除 API Key 后保存设置；这会沿用原有设置补偿流程。启动和刷新不会自动写桌面配置。若恢复记录或配置目录不可读写，先修正目录权限；不要用 root 启动应用绕过用户会话。

卸载或回退前，点击「停用系统快捷键」。仅移除仍属于应用的配置，其他应用的快捷键保留。如果应用已卸载，可以到 GNOME「设置 → 键盘 → 查看及自定义快捷键 → 自定义快捷键」删除“AI Selection Assistant · 翻译剪贴板”项。卸载脚本不遍历或改写其他用户的设置。

## 交付验证

使用现有 `scripts/build-linux-deb.sh` 构建，`scripts/verify-linux-deb.sh PACKAGE.deb` 验证实际包：小于 30,000,000 字节、包含可执行入口/有效桌面启动项及正确的 ELF 和工具运行依赖。`scripts/test-linux-deb.py PACKAGE.deb` 会在临时目录构造错误包，不安装包，也不运行维护脚本。

实际按键、完全退出后的冷启动、重新登录及升级属于真实 GNOME Wayland 验收。Xvfb 原生测试证明 X11 回归情况，不能代替这些步骤。测试使用本地模拟模型和合成文本，避免真实 API 费用或用户数据外发。

## 开发接口与本机状态

`get_shortcut_status` 是只读命令，返回 `backend`（native/gnome/manual）、`capable`、`enabled`、`desired`、`observed`、`status`、`message` 和固定 `command`。native 只有真实注册成功才报告 ready；GNOME configured 表示读回了系统配置，不能代替真实按键验证。界面 pending 只表示一次操作执行中。

`manage_shortcut` 接收 `action`（enable/reapply/disable/recover）与 `expectedShortcut`（当前已保存组合键），仅用于已安装应用的 GNOME 会话。状态刷新不写设置；操作与设置保存共享互斥范围，旧窗口提交过期组合键会被拒绝。成功后发出 `shortcuts-changed` 通知，读取接口不返回凭据。

`desktop-shortcut.json` 保存 version 和 enabled；独立桌面操作的非秘密日志是 `desktop-shortcut.recovery`。设置事务继续使用原有 settings.recovery，并在需要时携带桌面变更的补偿快照；不能把清除文件当作恢复操作。上述数据均不进入同步偏好。
