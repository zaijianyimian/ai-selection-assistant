# 手动验收

请使用自己的模型服务，只在设置的密码框中输入密钥，不要把真实 Key 写入测试文件、截图、命令行或提交内容。

## 通用桌面流程

1. 按 README 安装工具，执行 `npm ci`、`npm run build`、`cargo check --locked --manifest-path src-tauri/Cargo.toml`、`npm run tauri dev`。应出现原生窗口且没有「浏览器界面预览」提示。
2. 进入偏好设置，填写有效 Base URL、API Key、Model、Temperature、Timeout；保存应提示立即生效。
3. 完全退出后重启。非敏感字段应保留；密钥框应为空，但显示已保存。检查 `settings.json` 不包含 Key 字段和值。
4. 选择「测试连接」。有效配置返回成功和耗时；临时密钥框清空。测试不会保存未提交的修改。
5. 输入 `The JVM uses garbage collection to reclaim memory occupied by unreachable objects.`，开始翻译。应先显示加载，再显示完整译文及 JVM / garbage collection 等相关术语卡片。
6. 输入 `The weather is nice today.`，应正常翻译且不强制解释普通词语。模型表现不符合要求时记录服务商 / 模型及输出模式，不记录密钥。
7. 关闭术语解释并保存，再次翻译；术语数组应为空。更换目标语言后保存，译文应使用选定语言，术语解释仍为中文。
8. 复制译文并粘贴到临时文本文件，应与译文一致。
9. 选择深色并保存，主窗口和独立窗口均应变深；切回跟随系统可响应系统外观。
10. 打开悬浮窗；关闭它后再次通过快捷键唤起；关闭主窗口后从托盘重新打开。只有「退出应用」使进程结束。
11. 连续触发快捷键或按钮；正在进行的任务不应重复提交。关闭再打开窗口时仍应显示该任务的当前状态或结果。

## Windows 11 选区与剪贴板

使用发布的 exe 可直接验收，无需安装 Rust 或 MSVC；从源码进行 Windows 原生编译时需先安装 MSVC C++ 工具与 Windows SDK，并让 `cargo check` 成功。浏览器中的界面预览不能验证选区、系统凭据或 SQLite 原生命令。

1. 在记事本复制 `clipboard baseline`。
2. 在普通权限的浏览器 / VS Code / 可复制文字的 PDF 中选择另一段文本，按 Ctrl+Shift+Q 并松开按键。
3. 译文弹窗应读取新选区；返回记事本粘贴，内容仍为 `clipboard baseline`。富文本格式不在 MVP 恢复范围内。
4. 无选区触发快捷键，应提示未读到选区；不应拿旧剪贴板内容发送给模型。
5. 复制图片或文件后触发，应提示手动复制选区，避免破坏不能备份的内容。
6. 从管理员权限窗口捕获失败时，应提示权限 / 手动复制回退，应用继续可用。
7. 设置「仅剪贴板」并保存；先手动复制文字，触发快捷键，应该翻译该文字且不注入 Ctrl+C。
8. 更换快捷键并保存，旧快捷键停用、新快捷键可用。用另一应用占用目标快捷键，保存应报冲突并保留旧快捷键。部分第三方注册方式不会报告冲突，应以实机结果为准。

## DeepSeek Chat Completions

1. 从托盘完全退出旧版，启动 0.1.1 或更新版本。
2. 填写 Base URL `https://api.deepseek.com/v1`、Model `deepseek-flash`、输出「自动」，在密码框填写自己的密钥。
3. 测试连接应成功；保存时若临时密钥已清空，重新输入后保存。
4. 翻译 `The JVM uses generational garbage collection.`，检查译文与术语卡片；开启记忆后再检查术语入库与手动分析。
5. 若仍失败，记录 HTTP 状态码、错误字段 / 代码、Base URL、Model 和版本；不要提供 API Key。中转服务可能具有不同的模型名称和参数支持范围，可单独选择「JSON 模式」或「提示词 JSON」验证。

## Ubuntu X11

1. 登录「Ubuntu on Xorg」，选中一段文字，不显式复制，触发快捷键，应读取 PRIMARY。
2. 清空 PRIMARY 后手动复制，使用翻译剪贴板，应正常读取。
3. 复制译文后在另一应用粘贴；切换窗口后剪贴板内容仍应存在。
4. 关闭主窗口，验证托盘 / 再次启动可恢复，不产生两个常驻实例。

## Ubuntu Wayland

1. 登录 Wayland 桌面，确认已安装 `wl-clipboard`。
2. 在浏览器先 Ctrl+C，点击「翻译剪贴板」，应读取复制文字；若快捷键可注册也可尝试触发。
3. 快捷键不可用时应有清晰提示，应用内操作不受影响。设置系统自定义快捷键执行 `/path/to/ai-selection-assistant --translate-clipboard`，验证第二次启动转交到现有实例。
4. 复制译文后粘贴到其他应用，应得到原文对应译文。
5. 缺少 wl-paste / 复制非文字 / 剪贴板权限拒绝时应报错，无崩溃，无静默假结果。

## 模型失败与安全凭据

| 操作 | 期望 |
|---|---|
| 无效或已撤销的 Key | 明确提示 401 / 鉴权失败，不显示 Key 或服务端原始错误正文 |
| 无效模型 / 地址 | 提示模型或接口不存在 |
| 429 | 提示限流或额度不足 |
| 断网 / 关闭本机服务 | 网络错误，按钮可重试 |
| 响应慢于 Timeout | 超时错误，包含回退的总时间受限 |
| 不支持 Schema 的模型 | 自动回退一次，结果显示回退提示；手动提示词模式不再探测 |
| 响应非法 JSON / 缺字段 / 截断 | 可恢复解析错误；不生成演示译文冒充成功 |
| 空输入 / 超过 16,000 字符 | 阻止发送并提示 |
| Secret Service 锁定 / 不可用 | 提示解锁系统凭据存储，不写明文备用文件 |
| 勾选删除 Key 并保存 | 系统凭据删除，重启后显示未配置 |

密钥环测试请使用可丢弃测试凭据，测试后在应用中删除。真实外部模型调用可能计费。

## 术语记忆、分析与个性化

1. 从旧配置启动或全新启动，确认「记住专业术语」「个性化解释」「自动分析」均默认关闭。先翻译，再测试连接；本地术语数量应不变。
2. 开启记忆并保存，翻译 `The JVM performs garbage collection.`。进入术语记忆，应看到专业术语、独立词义、计数及最近时间。完全退出重启后仍存在；原文和完整译文应不恢复。
3. 对同一输入再次主动翻译，计数增加；同一次请求的 Schema 兼容重试只能记一次。测试连接不增加记录。
4. 保持记忆开启，关闭术语解释并保存后翻译专业文本：译文正常、卡片为空，记忆仍增加。普通文本不应强行生成普通词术语。
5. 在记忆页搜索名称、中文译名和领域，检查分页。把某词设为「正在学习」，再设为「已熟悉」，重启后反馈保留。不同领域或独立词义不会因名称相同而自动合并；措辞变化可能形成多条。
6. 点击「分析新增记忆」，应显示独立分析状态；期间仍能翻译。成功后查看主题、证据 ID 与版本。分析期间新翻译的记录仍待下次分析。积累超过一批数据时，继续点击处理剩余记录。
7. 将服务临时设为无效模型或本地测试服务返回错误 / 未知证据 ID，再分析；错误清晰，旧版本仍可使用。切换一个保留版本，应改变活动画像；不改变明确偏好或反馈。
8. 开启个性化，选择「入门」「后端工程」并保存；对已存术语翻译新文本，比较解释。通过可控本机模型服务检查请求：包含明确偏好、最多 8 个相关词及受限主题数据；`agent` 不能仅因 `reagent` 子串命中。检查上下文总长不超过 2000 字符。语义质量仍需用真实模型判断。
9. 在翻译或分析请求尚未返回时，删除术语或清空（先检查取消按钮，再确认）。返回后旧任务不能重新填回数据 / 画像；有效译文仍可显示。关闭记忆后同样停止旧任务保存，原有术语仍保留。
10. 使用可控本地模型配置自动分析（无需真实付费服务），积累至少 20 条新增出现 / 反馈记录并等待一个空闲检查周期（最多约 60 秒）；不足 20 条不请求。失败、重启、休眠恢复后 24 小时内不再自动尝试；应用退出时不会运行。24 小时边界已有单元测试，真实全天运行还需验收。
11. 在隔离测试用户的数据目录检查 `memory.sqlite3`：仅有 `terms`、`events`、`profiles`、`metadata` 与 SQLite 内部序号表；无原文、完整译文、解释、示例、API Key。数据库不可写或损坏时重启，翻译功能仍应可用并显示记忆存储警告。不要破坏日常使用的数据来做此项测试。

以上原生流程应分别在 Windows 11 和 Ubuntu 桌面验收；浏览器预览仅能验证界面和字体。不要把测试服务中的虚构响应当作真实模型语义质量验证。
