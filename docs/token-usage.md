# Token 用量与额度

在「偏好设置 → Token 用量」查看今日、本月及累计统计，也可按服务、模型或用途筛选。主窗口和翻译浮窗展示当前操作的输入、输出、合计；连接测试和最近一次手动/自动主题分析各自展示用量，失败时仍保留已收到的数字。

Token 是模型处理文本的单位，不等于字数。输入包括固定提示词和启用后的个性化摘要，输出包括结构化译文/术语解释及服务报告的推理明细。服务端缓存输入、推理输出是父计数的子集：输入 100（含缓存 20）、输出 30（含推理 10），合计为 130，不是 160。

本地翻译缓存命中不会请求模型，本次新增为 0 Token；重新请求模型会产生新用量。服务端上下文缓存仍属于模型请求，可能计费。连接测试、手动/自动分析及兼容降级重试同样可能消耗 Token；失败、拒绝、截断也不保证免费。缺失或无效字段显示未知，不按字符数估算，也不把未知当零。

这里统计的是本应用在本设备观察到的已报告用量，不是账户配额、剩余余额或服务商账单。其他设备、其他应用和未报告的消耗不在这些数字中。更换同一服务/模型的 Key 不会自动划分账户；金额请到服务商控制台核对。单次输出限制、上下文长度是请求限制，不代表可用余额。

统计从首次启用此功能开始，跨重启保留，不回填旧版历史。日期按每次 HTTP 尝试开始时的本机日期确定；跨午夜、后来修改时区或时钟不会移动已登记尝试。兼容重试跨日时分别计入各自的开始日期。

仅保存数字与必要服务/模型/用途分类，不保存原文、完整译文、提示词、Key、凭据摘要或原始响应。数据位于应用数据目录的独立 `usage.sqlite3`，不进入术语备份或多端同步。已终结尝试收据保留 7 天以防重复记账，日汇总保留至手动清空。禁用/清空术语或清空翻译缓存不影响统计。

「清空用量统计」需要再次确认，只清空用量并重新起算，不影响译文、缓存、术语、同步或模型配置，也不会取消已发送的请求。清空前开始的操作不会回填新的累计，其当前结果仍可显示本次用量并提示已排除。

统计存储故障不会阻止有效翻译。界面会提示未完整保存/暂不可用；已报告数字仍可在当前结果中阅读。请检查磁盘空间和数据目录后重试读取，必要时重启应用。应用不会为补统计重发模型请求，不会自动删除损坏或较新版本的统计文件。查看说明及已保存统计无需联网，不下载模型或分词器。

## 开发边界

- 共用 LLM 传输在每次实际 HTTP 尝试创建 ticket，在响应内容校验前提取 usage；drop、超时和读取失败终结为未知。Job/ConnectionTest/AnalysisStatus 持有 operation 快照，Translation 缓存不含 usage。
- 标准映射为 `prompt_tokens` / `completion_tokens` / `total_tokens`；缓存明细别名冲突只令该明细未知，总量冲突保留独立有效的输入/输出。缺失 total 不推算为服务报告值。质量状态由可选字段、覆盖计数与 overflow 表示，不记录原始错误内容。
- Token IPC 使用十进制字符串/null，前端用 BigInt 格式化。checked 累计溢出保留旧下界并警示。通知及读取不记账；服务身份摘要仅来自已验证的规范化 endpoint，与 API Key 无关。
- 独立 SQLite worker 使用 128 项有界队列、100 ms 数据库 busy timeout、2 秒查询/清空等待上限；模型请求不等待统计落盘，也不在 HTTP 期间持有数据库事务。队列满/存储异常必须标记累计缺口。
- `begin` 只登记 pending；`finish` 在事务中转换状态并更新日汇总。重复终结、已过期收据的迟到终结及旧 generation 均不能重复累计。启动仅把已登记的 pending 终结为未知，不重发请求。
- 翻译、连接测试、手动分析、自动分析分别归类；发送前校验/凭据/恢复/busy 失败不产生 attempt。同步和统计查询不调用模型。测试使用隔离目录、模拟 HTTP 服务和可替换时钟，不访问真实 Key。
