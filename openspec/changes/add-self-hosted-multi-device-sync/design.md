# Design

## Context

动机与用户确认范围见 proposal.md。本变更跨客户端、独立服务、数据迁移和部署，涉及认证及离线冲突，因此需要完整设计。

已观察到的实现：

- `src-tauri/src/memory.rs` 使用单 SQLite 工作线程；schema v1 的 terms/events/profiles 都使用本机递增 ID。术语唯一键为规范化名称、领域、独立词义、语言；出现记录以任务 UUID + term_id + kind 幂等。
- `read_term` 从 events 计算次数和最后出现时间，并以本机事件 ID 顺序取得最近反馈。分析快照也依赖本机事件游标；直接导入历史反馈会错误覆盖当前熟悉程度。
- 删除会物理移除术语/事件，并使本地 privacy epoch 与画像失效；尚无远端删除标记或设备身份。全文索引由本地触发器维护，可从术语重建。
- `settings_commit.rs` 已提供设置提交补偿/恢复；`SettingsView.vue` 已保护未保存草稿。模型 API Key 使用独立 OS keyring 条目，不进入配置 JSON。
- 桌面已有 reqwest/rustls、tokio、serde、rusqlite bundled 和 UUID；没有服务端项目。现有图标替换尚未构建，属于另一个已完成源码改动，不在本规划中重做。

## Goals / Non-Goals

**Goals:** 单所有者、个人多桌面设备、最终一致、离线可用；以服务器顺序版本解决因果和重复提交；所有远端内容作为有界数据处理；保留本地隐私与设置恢复保证；提供可实际部署的独立服务和验收证据。

**Non-Goals:** 多租户注册/团队共享/计费、手机客户端或网页词库、实时协作/WebSocket、WebDAV/S3 适配器、本次端到端加密、模型 Key/原文/完整译文同步、分析画像同步、全设备完全相同的快捷键/窗口位置。HTTPS 保护传输，VPS 管理者仍能读取服务端精简术语；不能宣传成服务器不可见的加密存储。

## Decisions

### 1. 独立 Rust 服务与个人工作区

新增 `server/` 独立 Cargo 项目（Axum/Tokio + 本地 SQLite），`crates/sync-protocol/` 只含可序列化协议类型/校验；两端以 path dependency 引用。保留桌面 `src-tauri/Cargo.lock` 与服务端独立锁文件，不引入根 workspace 来改变既有构建路径。服务器的 HTTP 框架/密码哈希依赖不进入桌面包。

一个部署只有一个所有者工作区，初始化产生不可变 `workspaceId`。每个设备有独立随机 `deviceId` 和令牌。客户端只需配置服务根 URL、专用同步密码和可辨识设备名称；不需要 SSH 账户或服务器任意文件路径。服务端数据路径固定在挂载的数据卷中。

选择专用服务而非文件覆盖，是为了在事务中分配顺序版本、验证字段更新基线、保存删除记录及提供可测试的设备撤销。WebDAV/S3 方案留待以后通过相同本地同步边界接入，本版不同时实现多种传输。

### 2. 启用与身份绑定

同步和后台同步均默认关闭。首次启用展示实际上传字段和服务端可读范围，连接测试只验证协议与认证，不上传词库、不改变模型配置。用户确认连接后才注册持久设备、保存令牌，并允许首轮本地数据合并。

`rememberTerms=false` 时暂停术语上传/拉取应用，包括已有 outbox；三项偏好仍可独立同步。开启同步不能自动开启记忆、个性化或自动分析。关闭同步取消/失效化进行中请求，已保留本地数据不删除。禁用前已在服务器成功提交的操作无法撤回，状态必须如实显示；关闭后迟到响应不能修改本地数据。

令牌与配置绑定规范化 HTTPS origin/base-path、workspaceId、deviceId。更改地址或发现 workspaceId 改变时暂停，不把旧工作区的 outbox 自动发到新服务器；需要明确选择保留本地但不迁移，或确认将当前精简数据导入新工作区。第一轮只合并现有词库，不执行整库覆盖。

### 3. 协议 v1 与版本边界

协议采用有版本 JSON 请求，时间戳仅用于显示，不用于决定冲突先后。服务端在事务中分配单调 `revision`，同时返回 `workspaceId`、`historyId`、`memoryGeneration`、协议版本。独立的 `historyId` 用于识别备份恢复/历史重建；`memoryGeneration` 只处理全局记忆清空，偏好不随之消失。

| 接口 | 行为 |
|---|---|
| `GET /healthz` | 最小存活状态，不含工作区内容、版本秘密或凭据 |
| `POST /v1/auth/check` | 专用密码验证和协议能力测试，不导入/上传数据，不持久注册设备 |
| `POST /v1/devices/enroll` | 验证密码后登记设备，返回一次性可见的设备令牌和工作区标识 |
| `GET /v1/devices` / `DELETE /v1/devices/{id}` | 查看设备及撤销设备访问；撤销不等于删除其已同步数据 |
| `GET /v1/changes?stream=...&after=...&until=...&limit=...` | 按服务器 revision 拉取固定上界的增量分页 |
| `POST /v1/push` | 提交最多 100 个带 opId/基线版本/代次的操作；批次全部接受或不修改业务数据 |
| `POST /v1/memory/reset` | 显式全局清空，使用 reset opId 和预期 generation，返回新 generation |

memory 与 preferences 使用分别提交的 cursor/inbox；接口一次只拉取一个 stream，记忆暂停时只拉偏好，不能跳过记忆条目后推进记忆游标。重新开启记忆时从原记忆游标追赶，先处理 reset/tombstone。

基础写操作为 observe（精简术语与一个出现事件）、feedback.set、term.delete 和 preference.set；reset 使用单独接口。observe 携带 termKey、当前已知 incarnation/删除基线和稳定 eventId；服务端先核验代次与删除基线，再在同一事务内创建/归并术语和出现记录。客户端不能用任意新 incarnation 绕过墓碑，未知旧词的离线 observe 也不能被当作已确认删除后的重新记忆。

首次拉取固定 `until=当前最大 revision`，后续页面沿用同一上界；新增变化留到下一轮。返回每页最多 500 条、1 MiB JSON，push 最多 100 操作且请求体最多 1 MiB。客户端和服务器都限制响应/请求实际读取字节，不能依赖 Content-Length。单条术语按既有保留字段上限验证：名称 120、译名 200、独立词义 120、语言 40 个 Unicode 字符；领域使用现有枚举。旧数据超界不静默截断，保留本地并明确报告不可同步项。

400 表示协议/字段错误；401 为需重新认证；409 为业务冲突/删除代次/历史失配并附脱敏结构化代码；413/429 分别为超限/限流；5xx/超时保留队列并退避。拒绝未知协议主版本，不将未知 JSON 作为设置或模型提示执行。

### 4. 数据身份与有界的字段合并

- `termKey` 为版本化规范身份元组 `[normalized,domain,sense,language]` 的确定性 UTF-8 编码哈希；规范化沿用当前 split-whitespace/join/lowercase 与字段 trim 规则并冻结为 key format v1。服务器同时核验元组，不能仅信任哈希。不同领域/词义/语言不合并，不用模型猜测同义词。
- 本地整数 term_id 保留，新增映射到 termKey 与服务器 `incarnation`；服务器对同一身份的首次创建分配当前 incarnation。相同身份但原词大小写/译名不同时，首个被服务器接受的展示值作为规范值；回包明确该值，两端收敛。未来人工编辑术语不在首期范围。
- 出现记录使用稳定 `eventId`，按集合并集去重。旧事件从原 job UUID + termKey + kind 确定性派生 ID，克隆过同一数据库的设备也不会把同一记录计两次；新事件持久生成全局 ID。次数从有效出现事件计算，不相加客户端 count 快照。
- 熟悉程度只同步当前显式状态和版本，不回放整段历史反馈。迁移时每个词提取当前最新反馈为一次 bootstrap 候选。服务端接受新反馈后，客户端仅在该词规范版本前进时追加一个幂等本地反馈事件；历史反馈/重复 pull 不能以导入顺序覆盖当前状态。本机事件游标与画像证据 ID 不跨设备同步。
- 每个反馈字段和每个偏好字段拥有各自 `valueRevision`。推送携带 baseRevision；若远端已改且值不同，返回冲突，不按机器时钟覆盖。相同值可作为幂等满足；不同字段可独立合并。冲突展示本地待提交值和当前服务器值，用户选择后生成新 opId 并基于最新版本重试；再次变化则再次提示。

### 5. 持久 outbox、导入事务与崩溃恢复

本地修改在同一 SQLite 事务内完成业务更新和 outbox 入队（已启用且绑定正确工作区时），使用现有 actor 串行化。首次同步只 enqueue 一次既有精简数据；重复启用不重复 bootstrap。重新启用同一工作区时，先把停用期间的本机差异按已保存基线入队，再拉取并核验远端代次/删除；已确认事件以稳定 ID 去重，不能只依赖内存中的“已开启”标记而漏掉离线本机修改。网络传输在 actor 事务外进行。

每次同步单飞：先固定上界拉取并原子提交每页的本地变化/游标，再推送 outbox，最后拉取规范回包之后的变化。记忆和偏好分别组成推送批次，旧 memoryGeneration 不阻止合法偏好继续同步。服务器用 `(workspaceId,opId)` 保存幂等收据：同 ID 同内容返回原接受结果，不生成新 revision；同 ID 不同内容拒绝。事务验证所有非重复操作后统一提交，网络响应丢失不会导致双重计数。

409 批次不提交新业务操作；将冲突项转入持久冲突队列后，其余项用原 opId 重新组成批次。处于歧义超时的批次必须先按原内容原 opId 重试取得收据，不能改变载荷再利用同 ID。pull 的页内容和 cursor 同事务持久化，重启可重放且不重复产生 events/outbox。

内存状态不能充当唯一进度。偏好文件提交不是数据库事务的一部分，使用第 7 节的 durable inbox；不得因其失败丢弃同页待处理偏好。

### 6. 删除、重新记忆与全局清空

同步开启时，界面区分“从同步词库删除”和“断开后仅清空本机”。单词删除和“清空全部设备”必须明确提示影响所有已连接设备；未开启同步时保留原本机删除行为。不能用含糊的“删除缓存”按钮提交全局删除。

单词删除发送基于 termKey/当前 incarnation 的 tombstone。服务端删除该 incarnation 的术语正文、出现记录和反馈，同时清理历史 changes 中的正文载荷；幂等收据只保存请求摘要、接受状态、标识和版本，不保存可被重放读取的正文。已清理的旧 changes 变成无正文 redacted 占位并推进 nextCursor；固定 until 只承诺版本遍历上界，不提供历史正文快照，后续删除 revision 仍必须送达。只保留去重/拒绝旧写入所需的非正文标识、版本和收据摘要；客户端应用删除时原子移除本地正文/索引，作废相关 outbox 和冲突内容，并递增本地 privacy epoch，阻止旧翻译/分析写回。首期不自动按天数清理 tombstone 或幂等收据，避免长期离线设备复活旧数据；备份副本需按运维保留策略单独清理。

已删除 incarnation 的离线 occurrence/feedback 不得创建新词。设备确认 tombstone 后，新的用户翻译可以发起带 `baseTombstoneRevision` 的重新记忆，服务器创建新 incarnation；旧 incarnation 的事件仍拒绝。并发重新记忆以相同已知 tombstone 为基线收敛到同一新 incarnation。单词删除不等于永久禁止今后有意积累该词。

全局清空通过 `memoryGeneration` 的 compare-and-set 更新处理。所有旧代次记忆写入拒绝；客户端先应用 reset 再考虑队列，作废旧代次的正文与待提交记忆，不把离线旧库当作首次导入。界面报告被作废的离线修改数量，不静默重新上传；之后的用户新翻译进入新代次。全局清空不删除三项偏好、设备凭据或本机模型配置。关闭同步的离线设备无法被即时远程擦除，保证是在它下次连接应用清空时生效。

### 7. 三项偏好与既有设置提交的集成

精确 allowlist：`theme`（system/light/dark）、`targetLanguage`（现有三项）、`explanationStyle`（现有四项）。`backgroundDomain`、模型 URL/名称/Key、temperature、超时、术语显示、privacy 开关、自动分析、快捷键和位置均不属于该集合。服务器和客户端拒绝额外字段，不接受整份 settings.json。

远端已接受偏好先入本地 SQLite durable inbox；通过既有设置锁和设置提交协调器只 patch 这三项，不携带 Key 替换/删除意图。文件保存失败时保留 inbox 和可恢复错误，下一次重试；导入标记禁止产生同一偏好的新上传回声。成功后发送既有 settings-changed 事件，主/浮窗一致；正在编辑的表单保留草稿并提示外部更新，旧译文 requestOptions 不变。

本地偏好保存与 outbox 跨文件/SQLite，扩展现有设置协调器的补偿/恢复机制，使失败可回滚，崩溃能识别并恢复待入队意图；恢复日志只记 allowlist 值/非敏感版本，不含模型配置或密钥。不能出现界面提示已同步却缺少持久操作的窗口。普通非同步设置保存不触发云端配置替换。

### 8. 模型与索引隔离

远端合并由显式同步触发，不能调用翻译/分析接口。导入术语/出现记录通过相同保留字段校验和索引触发器维护搜索；导入反馈变化使相关本地画像失效。会改变分析输入的导入页递增本地 privacy epoch、使在途画像提交失败；本地 term_id 保留，旧画像绝不带着跨设备 ID 导入。

同步不主动请求模型重建画像。既有自动分析仅在本机此前明确开启、仍符合本机阈值/24 小时限制时按原规则运行；测试同步本身时关闭该授权验证零模型请求。关闭记忆时不应用远端记忆，仍允许读取既有本地术语，隐私开关不被云端开启。

### 9. 认证、秘密与传输

服务端使用 Argon2id 保存应用同步密码的带盐哈希；专用管理命令从受限 secret 文件/交互输入初始化或轮换，不把明文密码写入 compose 示例/命令行/日志。参数采用明确的内存与并发上限，实施时在目标容器测量后固化参数和测试。密码更换撤销所有设备令牌，不修改 workspaceId 或词库；设备需重新登录，待提交本地修改保留。

设备令牌由 OS 随机源生成至少 256 位熵，只返回一次；服务端只保存摘要。客户端保存在独立 keyring 条目，前端仅得到已配置状态，密码框在测试/登录后清空，不持久保存登录密码。凭据存取失败不能启用半配置连接，使用补偿/恢复状态；若刚登记的令牌无法保存，尽力撤销该设备并报告清理结果，不能在后台无限登记孤立设备；不影响独立模型 Key，不以明文文件作备用。

服务端所有业务接口校验令牌和工作区；个人所有者设备可列出/撤销设备和执行已确认的数据删除，本版不是多角色权限系统。登录失败限流（默认每来源 IP 每分钟 5 次，整体同时最多 2 个密码验证）；业务请求默认每设备每分钟 60 次，429 带 Retry-After。限制设备数（默认 20）和数据卷/数据库大小（默认 1 GiB），达到配额拒绝新增写入但允许读取、删除和撤销；具体边界必须可测试。

生产客户端强制 HTTPS 和证书校验，禁止 URL 内嵌凭据/查询/片段及携带认证跟随重定向。HTTP 例外仅允许明确的 loopback 开发测试，不允许普通公网 HTTP 或“忽略证书”。模型传输配置与同步传输配置分别校验。请求体、Authorization、登录密码、原文不进入应用/反向代理日志，错误使用白名单结构化代码。

### 10. 调度、状态与退出

立即同步可用；后台同步另行 opt-in，默认应用启动后一次及每 60 秒一次（仅在已启用、非暂停时），本地修改 debounce 2 秒触发，单飞合并唤醒。网络错误采用带抖动指数退避 5 秒至 5 分钟；401 停止自动重试并提示重新登录，429 尊重 Retry-After；协议/历史错误暂停人工处理。每轮设置 30 秒网络预算并保留可续传分页进度，不阻塞翻译快捷键或 UI。

状态至少包含 disabled/idle/syncing/offline/needs-auth/conflict/paused/error，显示最后成功时间、本地待提交数量、冲突数量和脱敏失败原因。最后成功时间只在该轮应处理的页与操作已持久提交后更新；有冲突时报告“已同步其余内容，仍有 N 项冲突”，不显示无条件全部成功。应用退出不注册系统守护任务，重启从数据库恢复。

### 11. 部署、备份与恢复

交付 `server/Dockerfile`、`deploy/sync/compose.yaml`、Caddy 配置、无秘密的环境/secret 示例和中文手册。Compose 用独立内部网络连接服务和反向代理；只代理发布 80/443，数据服务端口不直接暴露公网；非 root 运行，挂载持久数据卷。实际 VPS 配置需要可解析域名与 HTTPS 证书条件，未具备时手册给出已有 TLS 代理接入方式，不关闭证书校验。

服务端 SQLite 只放服务本机持久卷；备份使用一致性备份接口或停写维护模式，不能直接复制正在写入的数据库。管理命令提供初始化、密码轮换、备份、恢复和状态检查；正常重启保留工作区/历史/幂等收据。

恢复旧备份属于显式运维操作：停服务、验证备份、迁移、生成新 historyId、撤销设备令牌后启动。客户端重新登录发现 historyId 改变必须暂停，显示本地/远端数据摘要并由用户确认恢复基线，不能沿用旧 cursor 或自动重放旧队列。备份恢复无法凭空恢复备份之后丢失的删除记录，因此不承诺跨历史自动合并；该限制明确写入手册。

服务端容器在本地隔离环境验证部署、重启、认证、TLS 配置及备份恢复后再提供 VPS 操作指导。真正连接/部署用户 VPS 的域名与访问方式在实施交付阶段取得；本规划阶段不请求密码、不登录、不开放端口。

## Risks / Trade-offs

- [个人服务器能读术语] → HTTPS、最小字段、明确首次授权；本版无 E2EE，不能暗示服务端盲存储。
- [离线并发不是立即一致] → 持久队列/固定上界分页/显式冲突；不承诺两台断网设备即时相同。
- [旧数据库含本机游标和反馈历史] → 稳定映射、只同步当前反馈、迁移与回放测试；不复制数据库字节或画像。
- [删除与幂等记录长期增长] → 首期保留不自动过期，提供配额/监控和删除正文；将安全压缩留到设备确认机制完善后。
- [离线新修改被全局清空作废] → 清空前提示全设备影响，重连明确报告数量，旧代次不静默重传。
- [偏好跨资源提交或同步回声] → durable inbox、提交协调器、origin 标记和故障注入；保留设置恢复门控。
- [同时运行旧版桌面程序] → schema v2 拒绝旧版本打开，提供迁移前一致性备份与明确降级手册。
- [图标与新增依赖增加包体] → 服务端依赖隔离、最终整包 stat <30,000,000 验收，不能用估算替代成品。

## Migration Plan

1. 先实现/测试协议与服务端，再接客户端。新增客户端可读 schema v1/v2；尚未启用任何同步时继续使用 v1 的本地行为。
2. 首次启用同步时（包括暂只处理偏好的记忆暂停设备），停止/失效化本地写入任务，通过 SQLite 一致性接口生成私有权限的 v1 备份；备份失败则不开始迁移，不上传任何数据。新建安装也先建立空本地数据库并走同一迁移路径；重开 v2 时不得由旧初始化逻辑把 user_version 写回 1。备份含精简术语，UI 显示保留位置和删除方法。
3. 单事务创建 term/event 映射、outbox、inbox、冲突、游标与代次等侧表，记录迁移完成并设 user_version=2；保留原 term_id、旧计数、反馈与画像。故障回滚为 v1，可再次安全尝试。联网合并前不失效旧画像；首次确实改变分析输入时再失效。
4. 通过稳定旧事件 ID/bootstrap 标记把既有数据入队，认证并核对工作区后合并。不上传 v1 备份文件、FTS shadow 表、原文或秘密。
5. 禁用同步仍可在 v2 本地使用；降级到旧程序需先退出新程序、备份当前 v2，再恢复 v1 备份，明确其不包含升级后的新修改。服务器升级/回退同样先备份并校验 schema，不让旧服务进程写新库。
6. 实施完成后运行全部回归、双客户端故障场景和容器演练；核对图标、最终 DEB 预算与依赖后才构建交付。发布或真实 VPS 部署不属于本轮规划授权。
