# Proposal

## Why

用户只有一台 VPS，希望配套提供同步服务，让多台桌面设备共享术语记忆和阅读偏好。当前只有本地 SQLite，直接覆盖数据库无法正确处理离线新增、重复计数、删除传播和本机编号差异。

## What Changes

- 新增独立的个人同步服务及 Docker Compose / HTTPS 部署方案；客户端配置服务地址和专用同步密码，登录后使用可撤销设备令牌，不使用 VPS 的 SSH 密码。
- 新增默认关闭的同步配置、连接测试、立即同步、可选后台同步和可恢复状态。设备离线时继续使用本地数据，待同步修改持久化，应用退出不唤醒系统。
- 同步精简术语、出现记录和显式熟悉程度反馈；新增稳定跨设备身份、幂等事件、按版本合并、冲突选择与删除标记。清空全部设备使用独立确认和同步代次，旧设备不能复活已删除内容。
- 只同步用户确认的 `theme`、`targetLanguage`、`explanationStyle` 三项偏好；API Key、同步凭据、模型地址、自动分析授权、记忆/个性化开关、快捷键和窗口位置保留本机。分析画像和全文索引留在各端，接收记忆变更后按本地规则失效/更新，不自动调用模型重建画像。
- **BREAKING（本地数据库降级）**：客户端在首次启用同步时引入 schema v2 的事务迁移及迁移前一致性备份；保留旧术语 ID/记录/反馈，旧版应用不能直接打开升级后的数据库，回退需恢复升级前备份。
- 服务端与桌面包分开交付，不增加模型或桌面运行时解释器；实现完成后统一验收图标及同步功能，最终 DEB 继续严格小于 30,000,000 字节。

## Capabilities

### New Capabilities

- `sync-configuration`: 服务连接、独立凭据、设备身份、用户授权、后台调度及同步状态。
- `cross-device-memory`: 精简术语/出现记录/反馈的跨设备合并、迁移、离线队列、冲突和删除传播。
- `preference-sync`: 三项偏好的版本同步、冲突选择及与本机设置提交/草稿保护的集成。
- `self-hosted-sync-service`: 个人工作区、认证、版本化增量接口、事务与资源边界、VPS 部署、备份恢复和运维。

### Modified Capabilities

无已建立的主规格（`openspec list --specs --json` 返回空）。既有 term-memory、provider-settings、memory-analysis 等要求保存在先前变更中，作为本次兼容约束引用，不改写其已完成记录。

## Impact

- Rust 客户端：`memory.rs` / `analysis.rs` / `settings_commit.rs` / `lib.rs`，新增同步协调、配置/凭据模块与 schema v2 迁移；保留 SQLite actor，网络请求不占用数据库事务。
- 前端：`SettingsView.vue` 或独立同步设置区、同步状态/冲突列表、`MemoryView.vue` 删除范围提示、Pinia 与原生事件；既有设置草稿和结果快照保护继续有效。
- 新增独立 `server/` Rust 服务、`crates/sync-protocol/` 精简协议类型、`deploy/sync/` 容器配置及部署手册。服务端依赖不进入桌面依赖树，不把 Tauri 工程改成需要构建服务器的根 workspace。
- 协议与持久化：单所有者工作区、设备令牌、服务器顺序版本、持久 outbox、删除代次与可恢复冲突；本地数据库和服务端数据卷分别备份。
- 验证：双客户端离线/并发/删除/重试/重启、认证与恢复故障、原生设置/搜索回归、容器部署演练和最终安装包预算。用户已明确授权本地实施与功能完成后构建；GitHub 发版和真实 VPS 部署不包含在当前实施授权中。
