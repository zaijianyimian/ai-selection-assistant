# Proposal

## Why

当前应用只展示翻译结果和费用提示，没有保留接口返回的 Token 用量，用户无法知道翻译、连接测试和主题分析分别消耗了多少。新增“使用说明＋每次及累计用量”，帮助用户理解模型请求与本地缓存的差别，同时避免将本机统计误当作账户余额或服务商账单。

## What Changes

- 在共用模型请求层采集服务返回的输入、输出、合计 Token，以及可选的服务端缓存/推理明细；未知数据明确显示“未知”，不按字符数猜测。
- 覆盖普通翻译、连接测试、手动主题分析和自动主题分析。兼容重试按实际 HTTP 尝试分别记录；响应有效用量先入账，再进行译文或画像解析，避免漏算截断、拒绝及解析失败的响应。
- 在主窗口/浮窗显示本次用量，在设置中展示今日、本月、累计统计及服务、模型、用途分类。用量按请求发起时的本机日期归属，累计在重启后保留；旧版本历史不补算。
- 本地缓存命中显示“本次新增 0 Token”，不重放首次请求的用量；刷新或重复接收窗口事件不增加累计。
- 新增 Token 说明，解释提示词、个性化信息、术语解释、分析与连接测试的消耗，以及本地缓存和服务商缓存的区别。
- 仅在本机保存数字统计和必要分类元数据，不保存原文、译文、提示词、API Key 或其摘要，不参与多端同步；提供独立、明确确认的清空操作。统计失败不得阻止有效翻译。
- 首版不查询账户余额，不估算金额，不配置额度上限或自动限额，不添加模型、分词器或统计专用网络请求。

## Capabilities

### New Capabilities

- `token-usage`: 模型请求用量的可信采集、缓存与重试计数、跨重启的本地聚合、清空与说明展示。

### Modified Capabilities

无。当前 `openspec/specs/` 尚无已归档主规格；本变更新增独立能力，延续现有 provider-settings 的凭据保护、memory-analysis 的并发/隐私约定及实际缓存行为，不改写它们的既有承诺。

## Impact

- 后端：`src-tauri/src/llm.rs` 的请求/降级循环；`lib.rs` 的 Job、连接测试与缓存分支；`analysis.rs` 的分析状态；新增独立用量模块和本地 SQLite 文件。
- 前端：`src/types.ts`、assistant store、翻译结果、连接测试和主题分析的用量展示，新增设置中的统计与说明组件。
- 兼容：usage 为可选附加数据，缺失、格式错误或服务商不支持时，原有翻译/分析能力继续可用；记忆数据库、同步协议、API Key 存储和默认授权不变。
- 依赖/交付：沿用 bundled SQLite，不引入模型或分词库；后续实现验收检查 Windows/Linux 和安装包小于 30,000,000 字节。本次仅创建规划文档，不实现、构建或发布。
