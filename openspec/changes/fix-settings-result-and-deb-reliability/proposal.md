# Proposal

## Why

0.1.1 的补充测试复现了设置草稿覆盖、旧译文语言标签错误，并发现设置保存失败仍可能清除画像的提交顺序问题。当前 DEB 还引用 GLIBC_2.39 却未声明 libc6 最低版本，需要在继续发布前修复数据一致性和安装兼容性。

## What Changes

- 设置保存采用可回滚的提交过程；后续凭据、快捷键、配置写入失败时，已有画像、分析游标和记忆 epoch 保持有效，成功提交后继续阻止旧任务写回。
- 设置页区分已保存基线与本地草稿；外部刷新保留未保存编辑，并提供明确的重新加载入口。
- 每个翻译任务保存目标语言及术语展示选项的请求快照；已有结果不再随当前设置被错误重标记。
- DEB 根据最终二进制和构建环境生成并检查带版本的动态库依赖；保留剪贴板和中文字体依赖，说明源码构建范围与预编译包验证范围。
- 为四类问题增加定向回归、故障注入和打包验收步骤。
- 不包含取消任务、多服务配置、流式翻译、OCR、术语导出等新增功能；不改动模型协议、隐私默认值及旧变更的完成状态。

## Capabilities

### New Capabilities

当前 `openspec list --specs` 无主规格，已有能力只存在于两个尚未归档的变更中。以下沿用其已有路径、只新增本次修复的契约，不复制或改写旧变更；`linux-packaging` 是新增能力边界。

- `provider-settings`: 设置提交与画像失效的一致性、失败回滚与明确的恢复错误。
- `desktop-experience`: 设置草稿保护、外部配置更新提示与主动重新加载。
- `technical-translation`: 翻译任务的不可变展示快照及跨窗口恢复。
- `linux-packaging`: 可核验的 DEB 运行库版本约束及产物兼容范围。

### Modified Capabilities

无已建立的 `openspec/specs/` 主规格需要修改。后续同步或归档应把这些新增要求与旧变更中同路径要求合并，不能覆盖旧要求。

## Impact

- 后端：`src-tauri/src/lib.rs`、`settings.rs`、`memory.rs` 中保存协调、故障注入边界、任务元数据；必要时新增聚焦的设置提交模块。
- 前端：`src/types.ts`、`src/stores/assistant.ts`、`SettingsView.vue`、`TranslationView.vue` 及相邻测试。
- 打包：`src-tauri/tauri.conf.json`、新增 Linux 构建/验包脚本，使用宿主发行版的 dpkg 工具核对依赖；Windows 打包行为保持兼容。
- 文档：README、手动验收与验证记录。当前本地测试报告提供 11 项前端、22 项 Rust 通过及两个失败探针的基线；保存一致性问题仍需实施前故障注入复现。
- IPC 增加任务展示元数据，由同一安装包内前后端同步升级；不迁移术语表，不保存原文、译文历史或明文凭据。
