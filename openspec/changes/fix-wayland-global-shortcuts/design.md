# Design

## Context

动机见 `proposal.md`。本变更同时涉及桌面配置、设置事务、单实例生命周期和界面，因此需要设计文档。

- `src-tauri/src/lib.rs` 无条件尝试初始化全局快捷键插件，并在初始化成功时设置 `shortcut_available=true`；真实注册错误只追加警告。`shortcut.rs` 使用的 Linux 后端来自 `global-hotkey` 的 X11 实现。
- `--translate-clipboard` 已覆盖冷启动和单实例转发，最终走 `start_job`，已有忙碌保护、恢复门禁、输入验证和错误呈现。GNOME 接入应复用此入口，不建立第二条翻译链路。
- `settings_commit::Services` 目前只有 register/unregister，事务以“预留新键、提交文件、注销旧键”工作。GNOME 同一持久路径上的更新不能直接套用此模型，否则提交后注销旧键可能误删新绑定。
- Wayland 捕获使用 `wl-paste`；现有规范要求先复制，窗口位置交给 compositor，快捷键不得同步到其他设备。
- 本机检查发现微信系统绑定使用 `gdbus` 通知一个带实例编号的地址，该地址当时无持有者。这只证明遗留绑定，不能证明微信每次启动弹窗的根因，也不能据此认定微信内部使用 Portal。
- 本机暴露了 GlobalShortcuts Portal，报告 version 1 且包含额外方法。接口存在不等于已完成会话绑定、权限复用或键事件投递验证。

## Goals / Non-Goals

**Goals:**

- 为已安装的 Ubuntu GNOME Wayland DEB 提供显式启用、持久存在的固定命令绑定。
- 把可探测的能力与实际配置状态分开，保留原生平台及设置补偿的已有行为。
- 对自身绑定的修改具备所有权检查和恢复记录；对启动、刷新和外部编辑采用只读检查。

**Non-Goals:**

- 本期不实现 Portal 会话、绑定或配置 UI，也不增加常驻中继服务。其他桌面提供手动命令，不扩大自动支持声明。
- 不自动改写用户在 GNOME 设置中的修改，不扫描并清理微信或历史手工绑定，不自动接管旧命令。
- 不改变选区获取、窗口定位、同步协议或模型权限边界；开发构建和非标准安装路径不自动写生产命令绑定。

## Decisions

### 1. 后端选择先判断 Wayland，再判断桌面与可用能力

复用项目已有 Wayland 判断，避免 `DISPLAY` 存在时误选 X11。Windows/X11 使用原生插件；GNOME Wayland 同时检查桌面标识、用户会话、`gsettings`、必要 schema 与 installed executable。GNOME 能力不完整以及其他 Wayland 桌面进入 manual 后端，显示固定命令和原因。

GNOME Wayland 不同时启用原生 X11 抓键，避免一次按键被两条路径处理。原生后端只有 register 成功才呈现 ready。检测工具失败不得阻塞应用启动或普通翻译。

选择 GNOME 固定命令，是为了复用持久系统配置和现有单实例入口。Portal 更适合将来的跨桌面扩展，但其 BindShortcuts 通常可能显示对话框，历史绑定查询也不等同于当前会话已激活；不能用“保存过就跳过绑定”的假设解决。参考：[官方 GlobalShortcuts 接口](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.GlobalShortcuts.html)。

### 2. 稳定的绑定身份与最小运行依赖

为本应用保留一个固定 relocatable schema 路径，例如 `/org/gnome/settings-daemon/plugins/media-keys/custom-keybindings/ai-selection-assistant/`，写入名称、规范化组合键和固定命令 `/usr/bin/ai-selection-assistant --translate-clipboard`。不使用 PID、随机路径、临时文件或会话 D-Bus 地址。

通过 Rust 子进程调用 `gsettings`，所有参数单独传递，不使用 `sh -c`；对 GVariant 使用受限的类型编码/解码，绝不执行其内容，也不拼接用户输入为 shell 命令。为查询和写入设置超时及输出上限。GNOME schema 由桌面提供，打包显式核对 `libglib2.0-bin` 与已有 `wl-clipboard` 运行依赖，不把 GNOME 桌面强制安装为所有 Linux 用户的依赖。

现有快捷键格式先转为统一修饰键与按键表示，再生成 GNOME accelerator。对无法可靠映射的输入报告不支持；不静默换键。冲突检查覆盖可读的 GNOME 自定义键和常见系统绑定，并明确其不能穷举 compositor 保留键。

相同专属路径和预期命令构成所有权基础。外部只改组合键时可展示其真实值，显式重新应用才恢复已保存值；外部把命令改成其他程序时，不覆盖、删除或 reset，该情况交由用户在系统设置中处理。手工创建的相同命令不自动收编，避免擅自改动用户配置。

### 3. 本机状态和用户操作

快捷键服务返回 backend、capability、desired trigger、observed trigger、status 和可操作错误。GNOME 状态至少包括 not-configured、configured、external-change、conflict、unavailable 和 recovery-required；pending 表示一次用户操作执行中。configured 表示读回命令和组合键一致，不宣称按键投递已验证。

新增独立的本机元数据，记录管理启用状态及版本；不得进入同步偏好白名单。默认不启用，保存现有 shortcut 值不等于授权写 GNOME 设置。用户未启用时可保存期望组合键，后续显式启用才写系统配置；启用后的改键随设置事务处理。

设置界面提供“启用系统快捷键”“刷新状态”“重新应用已保存快捷键”“停用系统快捷键”，展示命令、当前组合键和“先 Ctrl+C，再按快捷键”。启用/重新应用必须明确使用已保存值；存在未保存改键时提示先保存，避免套用旧值。操作期间阻止同一应用并发修改，失败给出可操作信息。

普通启动、进入设置和刷新都只读取桌面状态。不因本机记录仍为 enabled 就自动补建被删除的系统绑定，也不在每次启动弹确认窗。停用移除专属列表项及仍归本应用所有的路径值；应用退出不删除绑定。卸载说明提供先停用或手工删除的步骤，root 维护脚本不遍历用户桌面配置。

### 4. 将桌面变更纳入可补偿提交

把原生和 GNOME 操作抽象为可测试的 prepare/apply/rollback/finalize，而非对两种后端统一调用 unregister(old)。原生仍可预留新键再释放旧键；GNOME 在同一路径更新，finalize 不得删除刚写入的新值。

启用、改键和停用共用事务协调器：验证输入与能力，检查冲突/所有权，准备本地临时文件，在第一次外部写入前持久化非秘密 undo 记录，然后修改自身路径和列表成员关系，读回确认，最后提交本机元数据及相关设置。任一步失败都尽可能恢复此前一致状态。补偿成功后保留旧设置、凭据和术语状态；补偿失败保留 recovery-required，并沿用既有模型请求门禁，不能假报成功。

恢复记录包含操作阶段、本应用路径的旧值/预期新值、列表成员关系和本机元数据的恢复信息；不存 API Key、剪贴板或完整桌面命令列表。旧版恢复标记要继续兼容。检测到未完成操作时，启动只报告状态，由显式恢复/重试进行写入，不以“自动恢复”覆盖用户外部修改。

每次写全局 custom-keybindings 数组前重读、合并本应用项、检查变化，按有限次数重试；补偿也只撤销自身增删，保留新出现的其他路径。GSettings 多 key 操作没有跨进程事务，不能承诺消灭所有竞争窗口；检测到所有权改变或无法确认一致性时停止盲写并报告待恢复。测试必须覆盖并发编辑，而非简单用旧完整数组覆盖当前数组。

### 5. 冷启动与单实例转发的验收边界

继续使用已有入口和忙碌保护。GNOME 触发时只执行一次命令，运行中转发到同一个实例；退出后执行同一命令启动应用。冷启动路径应直接服务剪贴板任务，避免主窗口无关地抢焦点，捕获完成后再呈现翻译浮窗。空剪贴板、图片以及 wl-paste 失败必须报错且不调用模型。

用户会话的真实按键投递、冷启动、重新登录和升级是 Wayland 人工验收项；测试环境使用本地模拟 provider，不发送真实用户文本或使用真实密钥。Xvfb 中现有 X11 测试可以证明回归未发生，不能冒充 GNOME Wayland 验收。

## Risks / Trade-offs

- [GNOME 专用能力] → 对其他 Wayland 桌面展示手工配置；Portal 后续独立设计，不让本期包依赖整个桌面或新守护进程。
- [系统配置存在但快捷键被 compositor 占用] → 展示 configured 而非“保证可用”，检查可见冲突并提供改键/系统设置指引。
- [外部配置并发写入] → 自身条目级补偿、写前重读与读回检查；不能确认时显式恢复状态，不承诺全局原子性。
- [升级后旧进程仍运行] → 文档要求退出旧版本再验收，升级提示应说明需重启；本期不在安装脚本强杀用户进程。
- [工具或安装路径缺失] → 能力检查降级为 manual；DEB 校验固定入口与运行依赖，避免错误写入开发构建路径。
- [停用后卸载仍遗留被外部修改的项] → 尊重所有权并给出系统设置清理说明，不跨用户强制清理。

## Migration Plan

1. 保留现有 settings.json 的 shortcut 字段和格式，新元数据缺省为未管理；升级不自动创建 GNOME 绑定，不迁移/删除手工或微信条目。
2. 启用时先检测固定路径和命令，再完成可补偿写入；已存在的匹配项可幂等复用，已被其他命令占用则拒绝接管。
3. 通过原生回归、故障注入与 GNOME Wayland 验收后，再用既有脚本构建并检查最终 DEB 的实际字节数和依赖；本规划阶段不构建或发布。
4. 若需回退，先在新版本中停用本应用拥有的系统绑定，再安装旧版本；术语和模型配置保留。若无法启动应用，按文档在 GNOME 系统设置删除对应条目。回退不得以 root 改写其他用户设置。
