# Design

## Context

见 proposal.md。现有 run_job 是唯一用户翻译入口，llm 模块负责带结构化兼容降级的 HTTP 请求，测试连接复用传输。配置和凭据分别存储。Windows 验证环境缺少 MSVC/SDK，Linux WSL 可执行 Rust 检查。

## Goals / Non-Goals

在现有翻译链路接入可退出的记忆，数据库失败不能丢失有效翻译。不推断职业、身份或仅凭频率判断掌握程度；不训练模型，不做 RAG。不存原文上下文，不使用模型自由文本作为系统指令。

## Decisions

1. SQLite bundled 单工作线程，异步消息调用，不在数据库事务内请求网络。术语表以规范化名称、领域、独立词义区分同词异义；出现记录使用任务 UUID 幂等。术语反馈为 unknown/learning/known，只有用户可设置。
2. 每次翻译仍一次请求，新增 senseSummary；当前原文只用于本次 HTTP 请求和内存展示。解释关闭但记忆开启时仍检测术语。后端写入后返回 memoryId；数据库异常转为非致命警告。
3. 新设置默认关闭 rememberTerms、personalizeExplanations、autoAnalyze；开启自动分析需记忆开启。解释风格和背景领域为受限枚举。原有 settings.json 通过 serde default 迁移。
4. 分析使用聚合术语、计数、反馈、游标快照，不包含原文。按最多 100 个术语和有界记录前缀分批；分析输出是主题和证据 ID 的结构化数据，证据必须来自输入。保存版本、当前版本与成功游标；失败保留旧版本。手动和自动共用单一锁，不阻塞普通翻译。
5. 自动分析只在应用运行且翻译空闲时检查；首次具备至少 20 条新记录可运行，之后最少间隔 24 小时，尝试时间落盘，失败不无限重试；关闭应用不会唤醒操作系统。
6. 删除、清空、关闭记忆递增 privacy epoch，清空生成画像。翻译和分析开始时取得 epoch，提交必须匹配，防止删除后的旧请求重新写入。分析只推进快照实际覆盖的游标，新记录保留下一次处理。用户可查看版本并切换，版本失效后不可恢复删除的数据。
7. 个性化上下文总长最多 2000 字符，最多 8 个匹配术语；短英文词按单词边界匹配。引用本地词义/熟悉度及分析主题作为数据，显式背景/风格由固定提示模板表达。出现次数不推导熟悉度。

## Risks / Trade-offs

- 独立词义由模型生成，可能过细或合并错误 → 同名不同领域/词义分开，允许删除，不根据频率推断掌握。
- SQLite 是本地明文术语库 → 界面明确范围、可关闭和清空；不保存上下文或凭据。
- 第三方模型响应不合法 → schema 优先、prompt 兼容，严格解析和边界校验，旧画像继续有效。
- Windows 工具链缺失 → 实际执行 Windows 检查并报告阻碍，Linux 运行检查与自动测试，提供原生手动步骤，不宣称 Windows 通过。

## Migration Plan

首次访问创建 app_data_dir/memory.sqlite3，schema user_version=1。默认关闭新功能，旧配置可直接读取。关闭功能保留已保存数据；清空才删除；旧版本程序不读该数据库。API Key 始终留在系统凭据库。
